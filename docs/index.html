个人开源作品手记 · macOS / Swift 6 / Multi-Touch PWA

            
从 Unified Remote 到自研 AirTrackpad：如何用 Swift 与 Safari PWA 复刻 Mac 原生触控板手感

            

              这是一篇完整的工程复盘——记录我为什么决定重写一套无线触控板方案，以及如何在零第三方依赖的前提下，解决多指状态机消歧、三指抬指接力、Safari PWA 方向锁定和 macOS 26 Tahoe 底层接口兼容等真实工程问题。
            

          


          
一、痛点：为什么现有方案总差一口气？

          

            平时我几乎不把 Mac 触控板用力按下去，全部操作都靠「轻点点击 + 双指滚动/缩放 + 三指拖动 + 四指切屏/调度中心」完成。
            之前使用 Unified Remote 时，虽然基础移动与点击很稳，但在操作习惯上更像遥控鼠标：没有原生三指拖动的顺滑感，四指空间手势和调度中心也需要自己拼凑快捷键，始终跟 Mac 触控板隔着一层。
          

          

            如果为 iPhone 写一个原生 Swift App，虽然能直接用 UITouch 硬件采样，但个人开发者账号每次编译安装都有 7 天证书过期的维护负担。
            把手机端做成 Safari 全屏 PWA，把复杂且耗性能的惯性衰减、亚像素累加、原生事件合成留在 Mac 原生菜单栏 App，反而是体验和可维护性的最佳平衡点。
          


          
二、iPhone 触控板 UI 的克制：99% 纯黑 + 相对软件方向锁定

          

            手机屏幕比妙控板小很多，如果顶部或底部摆满功能按钮，四指扫屏时极易误触。因此触控端刻意只保留了一块 100dvh 的 OLED 纯黑区域（touch-action: none），只在右上角安全区外留一个极低对比度的小齿轮按钮。
          

          

            横放手机可以极大扩展三指和四指的横向操作空间，但很多用户平时会在 iPhone 控制中心开启「竖屏方向锁定」。
            我们在软件层加入了「锁定横屏（Home 条在右/左）」选项，并且专门解决了早期原型中的二次旋转陷阱：
            手势引擎不再盲目旋转 ±90°，而是读取当前视口宽高比与 screen.orientation.angle，仅当「目标锁定方向」与「系统当前实际视口方向」不一致时才做相对角度补偿。
          


          
三、魔鬼在细节里：状态机里的 4 个真实坑

          
    
            
  • 
              1. 错峰落指（Staggered Landing）：
              人类四指落屏并不是绝对同一毫秒，往往横跨 40~80ms。状态机必须通过 MAYBE_ONE → MAYBE_TWO → MAYBE_THREE → MAYBE_FOUR 的宽限窗口平滑晋升，才能保证四指切换桌面时不会先误触发一帧光标移动或三指左键按下。
            
    • 
            
  • 
              2. 轻点微抖动防吞（230ms Guard）：
              真实电容屏在手指轻点按下的 60~120ms 之间，因为指腹受压形变，几乎必然伴随 1~3px 的 touchmove 抖动。若过早按时间阈值切入移动态，轻点就会被直接吞掉；将时间晋升阈值与轻点判定窗口对齐（230ms）而位移阈值保持 5px，既保留零延迟拖动起手，又让快速轻点百发百中。
            
    • 
            
  • 
              3. 三指拖动「0.4s 抬指接力」：
              手机屏宽有限，选长文本或拖窗口到屏幕边缘常需要把手指抬起来换个位置继续拖。抬起三指后客户端启动可调定时器（默认 400ms）暂缓发送 dragEnd：期间三指放回立即取消定时器续拖；单指轻点则立即 flush dragEnd 并吞掉这次轻点；若网络断开或心跳超时（5s），Mac 端也会按 clientID 自动释放左键，绝不出现左键卡死。
            
    • 
            
  • 
              4. 幽灵触点与 Touch ID 轮换防跳变：
              iOS Safari 在四指贴边或系统弹窗时偶尔会丢失个别手指的 touchend。手势引擎每帧同步原生 event.touches 全量集合来自动清除幽灵触点；同时记录当前手势绑定的 activeTupleIds，当掌心误触导致三指或双指 ID 组发生变化时重置基线而不发出单帧大跳变。
            
    • 
          


          
四、macOS 底层合成与 Tahoe (macOS 26) 避坑记录

          
    
            
  • 
              隔离修饰键状态：
              全程使用 CGEventSource(stateID: .privateState)，避免 Mac 实体键盘正按着的 Shift/Option 污染手机端合成事件；三指拖动开始时显式设置 kCGMouseEventClickState = 1，防止刚单击完紧接着三指拖动时被系统当成双击拖选。
            
    • 
            
  • 
              亚像素滚动累加与 120Hz 惯性：
              CGEvent(scrollWheelEvent2Source:units:.pixel) 接收整型像素，直接强转会在慢速双指滑动时丢失小于 1px 的增量。通过 Swift 端浮点余数累加器配合 120Hz DispatchSourceTimer 指数衰减惯性循环，同时动态写入 field 137（自然滚动标志位），获得媲美原生触控板的阻尼感。
            
    • 
            
  • 
              CoreDockNotification 与 TN3179 隐私规避：
              实测 macOS 26 Tahoe 上，系统自带的 Apps.app 与 Dock.app 依然使用 CoreDockSendNotification（包括 com.apple.launchpad.toggle、com.apple.expose.awake 等），不依赖系统是否开启触控板 App Exposé 开关；而在网络层刻意不注册 Bonjour 服务，仅监听普通 TCP 入站连接并由系统 mDNSResponder 广播 .local，从而完美避开 Apple TN3179 指出的 ad-hoc 签名本地网络权限拦截问题。
            
    • 
          


          
五、如何直接用起来

          

            整个项目已以 MIT 协议完整开源：Mac 端仅依赖系统框架（SwiftPM 零外部依赖），Web 端为纯 ES Module 零构建工具链。
            你可以直接从 GitHub Releases 下载打包好的应用体验，也可以克隆源码在本地仅凭 Xcode Command Line Tools 一分钟构建属于自己的专属版本。
          

        

      

    


    
    

      

        

          
5 分钟上手与常见问题

        


        

          

            
1. 安装与首次运行

            
下载 AirTrackpad-v1.0.0-macOS-arm64.zip 解压拖入「应用程序」。因使用本地 ad-hoc 签名，首次运行请执行：

            
xattr -cr /Applications/AirTrackpad.app
open /Applications/AirTrackpad.app

          


          

            
2. 授予一次性辅助功能权限

            
点击顶部菜单栏触控板图标，按提示点击「授权辅助功能」，在「系统设置 → 隐私与安全性 → 辅助功能」勾选 AirTrackpad 即可。支持打开「开机自启」。

          


          

            
3. 校园网 / 个人热点打不开 .local？

            
部分校园网会屏蔽 mDNS 组播，而 iPhone 个人热点（Wi-Fi / USB 共享）则使用固定的 172.20.10.x 网段。只需在 Mac 弹窗「连接地址」条里点选对应 IPv4 胶囊后再扫码即可直连。

          


          

            
4. 某款软件无法双指捏合缩放？

            
不同软件对合成缩放事件的解析不同。展开 Mac 弹窗底部的「诊断与自测」，可在「捏合缩放引擎」中切换 原生手势、IOHID 缩放 或 ⌘+/⌘-，并立即用内置自测按钮验证。
